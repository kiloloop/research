# Always-On Agent Interop Matrix

**Date**: 2026-11-12

> Companion to the [Cross-Runtime Parity Matrix](runtime_capability_matrix.md). That matrix compares coding-agent runtimes a person drives session by session; this one compares **always-on agents** that keep running in the cloud, take work over chat, act on connected accounts, and come back to the person when a decision needs them. Source path: `runtime-comparison/always_on_agent_matrix.md`.

It covers OpenAI's dot, xAI's Grok Bot and Claude Duet, with rows for core capabilities and for interop surfaces: how work gets in, how results get out, what wakes each agent, where shared state can live, and who approves what.

---

## Evidence Tags

Each column is that agent's own self-report for one account; each agent edits only its own column.

| Tag | Meaning |
| --- | --- |
| `[V]` | Verified. The qualifier gives the basis: `(tested)` exercised in this account; `(available)` exposed in the agent's tools or settings but not exercised; `(documented)` stated in the vendor's official docs (pages in §4); `(policy)` stated in the agent's own operating rules. A slash joins bases, as in `(documented/tested)`; a comma adds a note on the source, as in `(available, integration inventory)` |
| `[I]` | Inferred: likely from what the agent can see, but neither tested nor documented |
| `[?]` | Unknown from where the agent sits; not a product-wide absence |
| `[N]` | Not available: the agent checked and cannot do this. `(tested)` marks an absence confirmed by a live check in this account |

## 4. Source Notes

- **OpenAI dot**
  - Official pages read: [Meet dots](https://learn.chatgpt.com/docs/dots), [Message your dot](https://learn.chatgpt.com/docs/dots/channels), [Tasks and memory](https://learn.chatgpt.com/docs/dots/tasks-and-memory), [Control your dot](https://learn.chatgpt.com/docs/dots/controls), [Connect computers and apps](https://learn.chatgpt.com/docs/dots/computers-and-apps).
  - Tested: authenticated reads of repository files, the drafting pull request, its discussion and check status; a file-update commit, verified as that pull request's remote head with the fetched file matching the submitted content.
  - Available: the integration inventory exposes GitHub file, PR and comment operations, Space page creation and sharing management, file creation, and Sites creation. This records presence only, not account access, successful creation, public availability or recipient access.
  - Not done: email or Slack test messages, external webhook calls, purchases, schedules, peer-agent conversations.
  - Independence: the drafting pull request's diff exposed the outside research notes before dot wrote its column, so this is not a blind self-report.
- **xAI Grok Bot**
  - Official pages read: [FAQ](https://docs.x.ai/grok-bot/faq), [Skills and routines](https://docs.x.ai/grok-bot/skills-routines-and-automations).
  - Tested: a GitHub connect, reads of a private repo, commits through a Cursor cloud agent, a lookup of its own email address, an HTTPS GET to `example.com`, a usage check, and browser sessions on the shared computer.
  - Not done: messages, email sends, webhooks, routines, phone calls, purchases, cross-bot login reuse.

- **Claude Duet**
  - Official pages read: none. Anthropic public docs were not consulted.
  - Tested: GitHub read, branch push and draft-PR creation on a private repo; a PR-activity subscription that delivered events into the thread; writes to the project-shared folder; parallel subagents; an outbound HTTPS probe refused by the egress proxy (403 on `example.com`).

  - Independence: the same thread wrote the outside research notes on the other two agents.
