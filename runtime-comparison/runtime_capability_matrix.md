# Cross-Runtime Parity Matrix

**Date**: 2026-09-04

> Maintained by the Claude Code and Codex changelog skills; source path: `runtime-comparison/runtime_capability_matrix.md`.

This is a capability comparison across the currently profiled agent runtimes (Claude Code, Codex, ZCode), compiled from each runtime's self-report and current runtime changelogs. Cursor support is scaffold-only until Cursor-owned onboarding lands, so Cursor is intentionally excluded from this comparison table; see the public [runtime capability schema](https://github.com/kiloloop/oacp/blob/main/docs/protocol/runtime_capabilities.md) for its conservative scaffold defaults.

Claude was last checked against Claude Code `v2.1.257` (verified in-session 2026-09-01 via `claude --version`; release notes reviewed through `v2.1.257`) with Claude Fable 5.1 (`claude-fable-5-1`, released 2026-09-01, serving model verified in-session on the 1M-context variant; the current Fable tier and the default Fable model in Claude Code since v2.1.257; API rate $10/$50 per MTok with $0.25/MTok cache reads; available to Pro, Max, Team, and Enterprise users and on the Claude API, AWS, Google Cloud, and Microsoft Foundry). Claude Opus 5 (`claude-opus-5`, released 2026-07-24) is the current Opus tier at $5/$25 per MTok with the same 1M context; Sonnet 5 (`claude-sonnet-5`, $2/$10 per MTok, 1M) completes the current lineup, with Fable 5 and Opus 4.8 now listed as legacy models. Fable 5.1's safeguards route queries flagged by the cybersecurity safeguards to Opus 4.8 and queries flagged by the biology safeguards to Opus 5.

Codex release coverage includes stable CLI `0.153.4` (2026-09-04), GPT-6 Astra (API release 2026-09-03), Codex changelog entries through 2026-09-04, and API changelog entries through 2026-09-03. Astra joins Sol, Terra, and Luna as a model choice for complex work across code, apps, and research. CLI `0.153.4` makes Astra the bundled default only when no model is explicitly configured. Access still depends on the account, sign-in method, client, rollout, and workspace administrator settings; a catalog entry does not establish access for every user.

The inspected Codex catalog declares a 272K context window for Astra and the GPT-5.6 family, with 95% usable context; this is separate from Astra's 1.05M API context and 128K maximum output. Standard multi-agent support, memories, apps, browser/computer use, goals, hooks, and workspace dependencies remain stable and enabled in the inspected runtime. Multi-agent V2 is disabled. Experimental context management, token budgets, and current-time reminders remain opt-in or unavailable in that inspection. Feature/catalog inspection establishes exposure, not a completed behavioral test; see Source Notes.

ZCode is profiled as a live in-session self-report by the ZCode runtime itself (GLM-5.3, `builtin:zai-coding-plan/GLM-5.3`), captured 2026-08-26 and re-verified in a second session the same day. The runtime is a desktop app only — ZCode `3.9.2` (`CFBundleVersion` 3.9.2.6069, verified via the app bundle's Info.plist; no standalone CLI binary on PATH) with auto-updates and release notes published only at zcode.z.ai/en/changelog. Its column reflects the tool surface, skills, and official plugin inventory available in those sessions (browser-use, document-skills, skill-creator, zcode-cua, zcode-guide; the plugin cache also ships android-emulator, ios-simulator, and restore-legacy-sessions, which are not skill-bearing in-session). The local provider config declares a 1M context and 128K output for GLM-5.3 on the coding-plan surface; pricing is not surfaced in-session and remains unstated.

## 6. Parity Gaps — Actionable Items

These are the highest-impact gaps where one runtime's limitation blocks effective collaboration:

| Gap                         | Affected Runtime(s)                | Impact                                                             | Proposed Fix                                                                   |
| --------------------------- | ---------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| No shared team/task-list primitive | Codex, ZCode                | Codex adds a task dashboard, queue, mentions, and parallel delegation but still lacks Claude-style named teammates and shared task lists (the latter opt-in on current Claude models); ZCode has concurrent subagents and agent-to-agent messaging but no shared team primitive | Agent cards — let runtimes discover and delegate to capable peers |
| Memory asymmetry            | Codex (partial), ZCode (handoff only) | Cross-session context degrades without MEMORY.md equivalent        | Standardize memory protocol; each runtime implements its own persistence layer |
| Sandbox blocks git/gh       | Claude                             | Every git/gh call needs sandbox configuration                      | Configure sandbox allowlists (`excludedCommands` globs such as `git *`, `gh *`) or disable sandbox for specific commands |
| Full browser automation gap | Claude without the Claude in Chrome extension; Codex without configured Browser, browser-extension, or site-tool access | Claude falls back to read-only WebFetch when the extension is absent or the session is API-key-authenticated; Codex browser control depends on an enabled surface and an approved context | Install the Claude in Chrome extension (`/chrome`), or delegate to a browser-capable runtime (configured Codex, or ZCode) after privacy review |
| Public skill coverage       | ZCode                              | `kiloloop/oacp-skills` ships `claude/` and `codex/` variants for all 5 public skills; no `zcode/` variants — ZCode users must rely on convention-based adoption | Add `zcode/` variants to each public skill, or document the convention-based pattern as a first-class install path |

## 8. Source Notes

- Codex release coverage is through CLI `0.153.4` and the 2026-09-04 entries in the [official changelog](https://learn.chatgpt.com/docs/changelog). The review covers every Codex entry after the prior 2026-08-27 checkpoint, including iOS `1.2026.237`; mobile queue/reconnect improvements do not change OACP authority. Workstation-specific app/CLI versions stay outside this public matrix.
- [Codex models](https://learn.chatgpt.com/docs/models) documents Astra and the GPT-5.6 choices, and distinguishes Max reasoning from Ultra delegation. [Workspace model availability](https://learn.chatgpt.com/docs/enterprise/workspace-model-availability#gpt-6-astra-in-enterprise) documents gated Enterprise access and administrator enablement. GPT-5.4/mini retired from ChatGPT-authenticated Codex on 2026-08-31; API-key access follows separate availability rules.
- [Astra's API model specification](https://developers.openai.com/api/docs/models/gpt-6-astra) supplies context, output, supported efforts, and token rates. The model catalog inspected on 2026-09-04 declares `context_window: 272000` and `effective_context_window_percent: 95` for Astra, Sol, Terra, and Luna; no local context-window override was configured. This is catalog evidence, not an executed maximum-context probe or serving-model attestation. Feature inspection found experimental context management disabled; asynchronous questions were exposed in the parent session but not its research subagent, so availability must be checked in each session.
- [Experimental context management](https://learn.chatgpt.com/docs/models#experimental-context-management) adds task notes and retrieval of earlier task content. It defaults off, needs a supported client, eligible ChatGPT sign-in and a new task, and does not replace OACP durable memory. The Codex models page names Plus/Pro and excludes Business, Enterprise, and API-key sign-in at launch; the [configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference) additionally names Pro Lite, while [CLI 0.153.0](https://github.com/openai/codex/releases/tag/rust-v0.153.0) excludes custom providers and temporary structured threads. Eligibility must be checked before adoption; the experiment was not enabled or behaviorally tested here.
- Astra's [API migration guide](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra) requires Responses for tools, omits `none`/`minimal` reasoning and sampling/log-probability controls, and excludes Fast mode with EU data residency. API asynchronous tools, WebSocket steering, and cache-preserving effort changes require application integration; they do not prove that a Codex session exposes equivalent tools. [API changelog](https://developers.openai.com/api/docs/changelog) coverage extends through 2026-09-03.
- Conditional thread credit/cost estimates are documented in [CLI 0.148.0](https://github.com/openai/codex/releases/tag/rust-v0.148.0). [Codex pricing](https://learn.chatgpt.com/docs/pricing) describes ChatGPT credits separately from API token charges. Astra Fast's credit multiplier is 2.5x; the API model specification lists 2x applicable API rates. CLI `0.153.2` corrected a displayed speed description only. Tool charges, cache-write billing, and input above 272K can change API cost; do not infer a session bill from the base rates in the table.
- MCP and permission changes are documented in [CLI 0.151.0](https://github.com/openai/codex/releases/tag/rust-v0.151.0), [0.152.0](https://github.com/openai/codex/releases/tag/rust-v0.152.0), and [0.153.0](https://github.com/openai/codex/releases/tag/rust-v0.153.0). They include tool-result limits, remote marketplaces, opt-in `update_plan`, model-gated asynchronous questions, and account-scoped remembered approvals. These are source-confirmed changes; permission-preservation and reconnect regressions were not independently exercised. [Auto-review](https://learn.chatgpt.com/docs/sandboxing/auto-review) remains distinct from OACP admission and review authority.
