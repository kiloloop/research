# Cross-Runtime Parity Matrix

**Date**: 2026-11-24

> Maintained by the Claude Code, Codex, and ZCode changelog skills; source path: `runtime-comparison/runtime_capability_matrix.md`.

This is a capability comparison across the currently profiled agent runtimes (Claude Code, Codex, ZCode), compiled from each runtime's self-report and current runtime changelogs. Cursor support is scaffold-only until Cursor-owned onboarding lands, so Cursor is intentionally excluded from this comparison table; see the public [runtime capability schema](https://github.com/kiloloop/oacp/blob/main/docs/protocol/runtime_capabilities.md) for its conservative scaffold defaults.

Claude was last checked against Claude Code `v2.1.322` (verified in-session 2026-11-10 via `claude --version`; release notes reviewed through `v2.1.322`) with Claude Opus 5.5 (`claude-opus-5-5`, the session's model on a 1M-context plan; serving model verified in-session). Fable 5.2 (`claude-fable-5-2`, released 2026-11-09, the default Fable model in Claude Code since v2.1.321) is the current Fable tier at $8/$40 per MTok with $0.20/MTok cache reads, a 1M context, and 128K maximum output, on the Claude API, AWS, Google Cloud, and Microsoft Foundry; its Claude API default effort is `high`, and Anthropic sets `medium` in Claude Code and the Claude apps. Claude Code moves saved Fable 5.1 picks to `fable` (on Team and Enterprise plans once the organization allows it). Opus 5.5 (`claude-opus-5-5`, released 2026-09-22, the default Opus model in Claude Code since v2.1.280) is the current Opus tier at $4/$20 per MTok with $0.20/MTok cache reads, a 1M context, and 128K maximum output; its Claude API default effort is `medium`. Sonnet 5.5 (`claude-sonnet-5-5`, released 2026-09-28, the default Sonnet model on the Claude API and the `sonnet` alias in Claude Code since v2.1.284) is the current Sonnet tier at $2/$10 per MTok with $0.10/MTok cache reads (5% of base input; $0.20 until early October 2026), a 1M context, and 128K maximum output; its Claude API default effort is `high`, and Anthropic sets `medium` in Claude Code and the Claude apps. Haiku 5.5 (`claude-haiku-5-5`, released 2026-10-07, the default Haiku model on the Claude API and the `haiku` alias in Claude Code since v2.1.293) completes the current lineup at $0.10/$0.50 per MTok with $0.01/MTok cache reads for prompts up to 100K tokens ($0.50/$2.50 above), a 1M context, and 128K maximum output; its Claude API default effort is `medium`. Fable 5.1, Fable 5, Opus 5, Opus 4.8, Sonnet 5, and Haiku 4.5 are among the legacy models. Fable 5.2 answers a query blocked by the cybersecurity safeguards with Opus 4.8 and one blocked by the biology safeguards with Opus 5, as Fable 5.1 did, with about 55% fewer blocks than Fable 5.1; Sonnet 5.5's cybersecurity safeguards visibly fall back to Sonnet 5 on higher-risk tasks.

Codex coverage extends through stable CLI `0.169.0` (November 13) and the November 17, 2026 release of GPT-6.2 Astra and Sol. Astra targets difficult end-to-end work, Sol everyday multistep tasks, GPT-6.1 Terra visual and computer-use workflows, and GPT-6 Luna focused high-volume tasks. Access depends on the client, sign-in method, plan and workspace policy.

Default Codex context is 272K for GPT-6.2 Astra and 500K for GPT-6.2 Sol and GPT-6.1 Sol. The November 17 catalog also lists 500K for GPT-6.1 Terra. These are model defaults. A turn’s serving model, available context and enabled tools depend on its runtime. The November feature check found native delegation, memories and hooks enabled. Multi-agent V2, external memory import, token budgets, current-time reminders and experimental context management were disabled.

ZCode is profiled as a live in-session self-report by the ZCode runtime itself (GLM-5.4, `account:zai-individual-coding-plan/GLM-5.4`), captured 2026-11-24 (previous capture 2026-10-09 on GLM-5.3). The runtime is a desktop app only — ZCode `4.0.0` (`CFBundleVersion` 4.0.0.10870, verified via the app bundle's Info.plist; no standalone CLI binary on PATH) with auto-updates and release notes published only at zcode.z.ai/en/changelog; eight changelog entries have landed since the previous capture (`3.15.1` through `4.0.0`), headlined by GLM-5.4 arriving pre-configured on the Coding Plan with vision (v4.0.0), a session-management tool and worktree support (v3.18.2), and the official ZCode Sites plugin (v3.17.2). Its column reflects the tool surface, skills, and official plugin inventory loaded in this session (browser-use, documents, pdf, presentations, spreadsheets, plugin-creator, skill-creator, zcode-guide, and zcode-site, plus the app-bundled dynamic-workflows skill and the node-repl-host and image-search MCP/SDK plugins; computer-use, visualize, and design are cached with skill directories but were not loaded in this session, and the former document-skills and zcode-cua plugins remain cached but are no longer skill-bearing). The marketplace registry additionally lists `claude-plugins-official` (anthropics/claude-plugins-official), so Claude-directory plugins can be installed into ZCode (since v4.0.0 the plugin store displays plugins by login region). GLM-5.4, Z.ai's first Loop Transformer flagship, lists a 1M context, 128K maximum output, and video/image/text/file input on its model page; the local provider config still declares only GLM-5.3 and GLM-5.3-Flash, so the GLM-5.4 figures come from that page rather than the client catalog. The host model list offers GLM-5.4 on the individual coding plan alongside GLM-5.3 and GLM-5.3-Flash, each with low/high/max reasoning levels (default max); pricing is not surfaced in-session and remains unstated.
