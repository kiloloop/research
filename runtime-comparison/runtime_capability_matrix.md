# Cross-Runtime Parity Matrix

**Date**: 2026-11-10

> Maintained by the Claude Code, Codex, and ZCode changelog skills; source path: `runtime-comparison/runtime_capability_matrix.md`.

This is a capability comparison across the currently profiled agent runtimes (Claude Code, Codex, ZCode), compiled from each runtime's self-report and current runtime changelogs. Cursor support is scaffold-only until Cursor-owned onboarding lands, so Cursor is intentionally excluded from this comparison table; see the public [runtime capability schema](https://github.com/kiloloop/oacp/blob/main/docs/protocol/runtime_capabilities.md) for its conservative scaffold defaults.

Claude was last checked against Claude Code `v2.1.322` (verified in-session 2026-11-10 via `claude --version`; release notes reviewed through `v2.1.322`) with Claude Opus 5.5 (`claude-opus-5-5`, the session's model on a 1M-context plan; serving model verified in-session). Fable 5.2 (`claude-fable-5-2`, released 2026-11-09, the default Fable model in Claude Code since v2.1.321) is the current Fable tier at $8/$40 per MTok with $0.20/MTok cache reads, a 1M context, and 128K maximum output, on the Claude API, AWS, Google Cloud, and Microsoft Foundry; its Claude API default effort is `high`, and Anthropic sets `medium` in Claude Code and the Claude apps. Claude Code moves saved Fable 5.1 picks to `fable` (on Team and Enterprise plans once the organization allows it). Opus 5.5 (`claude-opus-5-5`, released 2026-09-22, the default Opus model in Claude Code since v2.1.280) is the current Opus tier at $4/$20 per MTok with $0.20/MTok cache reads, a 1M context, and 128K maximum output; its Claude API default effort is `medium`. Sonnet 5.5 (`claude-sonnet-5-5`, released 2026-09-28, the default Sonnet model on the Claude API and the `sonnet` alias in Claude Code since v2.1.284) is the current Sonnet tier at $2/$10 per MTok with $0.10/MTok cache reads (5% of base input; $0.20 until early October 2026), a 1M context, and 128K maximum output; its Claude API default effort is `high`, and Anthropic sets `medium` in Claude Code and the Claude apps. Haiku 5.5 (`claude-haiku-5-5`, released 2026-10-07, the default Haiku model on the Claude API and the `haiku` alias in Claude Code since v2.1.293) completes the current lineup at $0.10/$0.50 per MTok with $0.01/MTok cache reads for prompts up to 100K tokens ($0.50/$2.50 above), a 1M context, and 128K maximum output; its Claude API default effort is `medium`. Fable 5.1, Fable 5, Opus 5, Opus 4.8, Sonnet 5, and Haiku 4.5 are among the legacy models. Fable 5.2 answers a query blocked by the cybersecurity safeguards with Opus 4.8 and one blocked by the biology safeguards with Opus 5, as Fable 5.1 did, with about 55% fewer blocks than Fable 5.1; Sonnet 5.5's cybersecurity safeguards visibly fall back to Sonnet 5 on higher-risk tasks.

Codex runtime capability coverage is through stable CLI `0.165.0` (2026-10-27), reviewed on 2026-10-29, including the GPT-6.1 Terra launch. Astra targets demanding end-to-end work; GPT-6.1 Sol targets complex repeated work; Terra targets writing, visual understanding and computer use; Luna targets focused, high-volume tasks. Catalog defaults and model access depend on client, account, sign-in method and administrator settings; a configured model does not attest the model serving a turn.

The Codex catalog inspected on 2026-10-29 declares 500K context for GPT-6.1 Sol and Terra and 272K for Astra, previous GPT-6 Sol and Luna, each with 95% effective context. Public Codex documentation independently specifies Sol's 500K default. Their API specifications list 1.05M context and 128K maximum output. Sol/Terra catalog defaults are `low`, while their API default is `medium`; actual task settings can differ. These are catalog/specification observations, not maximum-context tests. Standard multi-agent, memories and hooks were enabled in the scoped feature check; multi-agent V2, external-agent memory import, experimental context management, token budgets and current-time reminders were disabled. Check the exposed tool surface in each session.

ZCode is profiled as a live in-session self-report by the ZCode runtime itself (GLM-5.3, `account:zai-individual-coding-plan/GLM-5.3`), captured 2026-10-09 (previous capture 2026-08-26, re-verified in a second session the same day). The runtime is a desktop app only — ZCode `3.14.5` (`CFBundleVersion` 3.14.5.7961, verified via the app bundle's Info.plist; no standalone CLI binary on PATH) with auto-updates and release notes published only at zcode.z.ai/en/changelog; eight releases have landed since the previous capture (`3.10.2` through `3.14.5`), headlined by dynamic multi-agent workflows (v3.14.0). Its column reflects the tool surface, skills, and official plugin inventory available in this session (browser-use, documents/pdf/presentations/spreadsheets, plugin-creator, skill-creator, zcode-guide, and the app-bundled dynamic-workflows skill; the plugin cache also ships computer-use, node-repl-host, and image-search as MCP/SDK-bearing plugins plus android-emulator, ios-simulator, and restore-legacy-sessions, while the former document-skills and zcode-cua plugins remain cached but are no longer skill-bearing). The marketplace registry additionally lists `claude-plugins-official` (anthropics/claude-plugins-official), so Claude-directory plugins can be installed into ZCode. The local provider catalog declares GLM-5.3 and GLM-5.3-Flash (text/image/video input) on the coding-plan surface, each with a 1M context and 128K output and low/max/high reasoning variants (default max); pricing is not surfaced in-session and remains unstated.

ZCode loads skills from its plugin cache plus four conventional directories — user scope `~/.zcode/skills/` then `~/.agents/skills/`, workspace scope `<repo>/.zcode/skills/` then `<repo>/.agents/skills/` (`.zcode` scanned before `.agents`, first same-named skill wins, discovery at session start) — using the same SKILL.md + YAML frontmatter format. The `~/.agents/skills/` overlap means skills shared with Codex load in ZCode unchanged, so convention-based adoption is straightforward even without packaged variants (verified live 2026-08-26: a Codex-shared skill symlinked into `~/.agents/skills/` and a ZCode-only skill symlinked into `~/.zcode/skills/` both load; re-verified live 2026-10-09 with user-scope skills from both directories loaded in one session).
