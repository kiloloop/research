# Cross-Runtime Parity Matrix

**Date**: 2026-09-22

> Maintained by the Claude Code and Codex changelog skills; source path: `runtime-comparison/runtime_capability_matrix.md`.

This is a capability comparison across the currently profiled agent runtimes (Claude Code, Codex, ZCode), compiled from each runtime's self-report and current runtime changelogs. Cursor support is scaffold-only until Cursor-owned onboarding lands, so Cursor is intentionally excluded from this comparison table; see the public [runtime capability schema](https://github.com/kiloloop/oacp/blob/main/docs/protocol/runtime_capabilities.md) for its conservative scaffold defaults.

Claude was last checked against Claude Code `v2.1.280` (verified in-session 2026-09-22 via `claude --version`; release notes reviewed through `v2.1.280`) with Claude Opus 5.5 (`claude-opus-5-5`, released 2026-09-22, the default Opus model in Claude Code since v2.1.280; serving model verified in-session on the 1M-context variant). Opus 5.5 is the current Opus tier at $4/$20 per MTok with $0.20/MTok cache reads, a 1M context, and 128K maximum output; its Claude API default effort is `medium`. Claude Fable 5.1 (`claude-fable-5-1`, released 2026-09-01; the current Fable tier and the default Fable model in Claude Code since v2.1.257; API rate $10/$50 per MTok with $0.25/MTok cache reads; available to Pro, Max, Team, and Enterprise users and on the Claude API, AWS, Google Cloud, and Microsoft Foundry). Sonnet 5 (`claude-sonnet-5`, $2/$10 per MTok, 1M) and Haiku 4.5 complete the current lineup, with Fable 5, Opus 5, and Opus 4.8 now listed as legacy models. Fable 5.1's safeguards route queries flagged by the cybersecurity safeguards to Opus 4.8 and queries flagged by the biology safeguards to Opus 5.

Codex runtime capability coverage remains through stable CLI `0.153.4` (2026-09-04), while model coverage adds GPT-6 Sol and Luna (API release and Codex rollout 2026-09-22). Astra remains the hardest-work tier, Sol targets complex coding and agentic work, and Luna targets focused, high-volume tasks; GPT-5.6 choices remain available during the rollout. CLI `0.153.4` made Astra its bundled default when no model was configured, a version-specific observation rather than a claim about newer clients. Access depends on plan, sign-in method, client, rollout, and workspace administrator settings.

The Codex catalog inspected on 2026-09-04 declared a 272K context window for Astra and the GPT-5.6 family, with 95% usable context. The GPT-6 Astra, Sol, and Luna API specifications each list a 1.05M context window and 128K maximum output; Sol and Luna's active Codex context windows were not independently verified. Standard multi-agent support, memories, apps, browser/computer use, goals, hooks, and workspace dependencies remain stable and enabled in the inspected runtime. Multi-agent V2 is disabled. Experimental context management, token budgets, and current-time reminders remain opt-in or unavailable in that inspection. Feature/catalog inspection establishes exposure, not a completed behavioral test; see Source Notes.

ZCode is profiled as a live in-session self-report by the ZCode runtime itself (GLM-5.3, `builtin:zai-coding-plan/GLM-5.3`), captured 2026-08-26 and re-verified in a second session the same day. The runtime is a desktop app only — ZCode `3.9.2` (`CFBundleVersion` 3.9.2.6069, verified via the app bundle's Info.plist; no standalone CLI binary on PATH) with auto-updates and release notes published only at zcode.z.ai/en/changelog. Its column reflects the tool surface, skills, and official plugin inventory available in those sessions (browser-use, document-skills, skill-creator, zcode-cua, zcode-guide; the plugin cache also ships android-emulator, ios-simulator, and restore-legacy-sessions, which are not skill-bearing in-session). The local provider config declares a 1M context and 128K output for GLM-5.3 on the coding-plan surface; pricing is not surfaced in-session and remains unstated.

## 6. Parity Gaps — Actionable Items

These are the highest-impact gaps where one runtime's limitation blocks effective collaboration:

| Gap                         | Affected Runtime(s)                | Impact                                                             | Proposed Fix                                                                   |
| --------------------------- | ---------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| No shared team/task-list primitive | Codex, ZCode                | Codex adds a task dashboard, queue, mentions, and parallel delegation but still lacks Claude-style named teammates and shared task lists (the latter opt-in on current Claude models); ZCode has concurrent subagents and agent-to-agent messaging but no shared team primitive | Agent cards — let runtimes discover and delegate to capable peers |
| Memory asymmetry            | Codex (partial), ZCode (handoff only) | Cross-session context degrades without MEMORY.md equivalent        | Standardize memory protocol; each runtime implements its own persistence layer |
| Sandbox blocks git/gh       | Claude                             | Every git/gh call needs sandbox configuration                      | Configure sandbox allowlists (`excludedCommands` globs such as `git *`, `gh *`; since v2.1.277 a compound command is exempt only when every part matches, so run git/gh as single commands) or disable sandbox for specific commands |
| Full browser automation gap | Claude without the Claude in Chrome extension; Codex without configured Browser, browser-extension, or site-tool access | Claude falls back to read-only WebFetch when the extension is absent or the session is API-key-authenticated; Codex browser control depends on an enabled surface and an approved context | Install the Claude in Chrome extension (`/chrome`), or delegate to a browser-capable runtime (configured Codex, or ZCode) after privacy review |
| Public skill coverage       | ZCode                              | `kiloloop/oacp-skills` ships `claude/` and `codex/` variants for all 5 public skills; no `zcode/` variants — ZCode users must rely on convention-based adoption | Add `zcode/` variants to each public skill, or document the convention-based pattern as a first-class install path |

## 8. Source Notes

- General Codex runtime capability coverage is through CLI `0.153.4` and the 2026-09-04 entries in the [official changelog](https://learn.chatgpt.com/docs/changelog). The GPT-6 Sol/Luna model update uses the [2026-09-22 Codex rollout](https://learn.chatgpt.com/docs/changelog#codex-2026-09-22-gpt-6-sol-luna) and [API release](https://developers.openai.com/api/docs/changelog); it does not imply adoption of every intervening CLI capability. Workstation-specific app/CLI versions stay outside this public matrix.
- [Codex models](https://learn.chatgpt.com/docs/models) distinguishes Astra, GPT-6 Sol, GPT-6 Luna, the still-available GPT-5.6 choices, Max reasoning, and Ultra delegation. Sol/Luna roll out to Plus, Pro, Business, Enterprise, and Edu; Free and Go have Luna in the desktop app when available. [Workspace model availability](https://learn.chatgpt.com/docs/enterprise/workspace-model-availability) documents Enterprise administrator enablement. GPT-5.5 retires from ChatGPT-signed-in Codex on 2026-10-14 but remains available through the API; GPT-5.4/mini retired from ChatGPT-authenticated Codex on 2026-08-31.
